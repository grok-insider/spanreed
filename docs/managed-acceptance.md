# Managed transport acceptance

Run from the canonical fabrials-libs checkout:

```sh
bun scripts/qualify-managed.ts /path/to/spanreed /path/to/grok-desktop-portable /path/to/remote-crypto-dist
```

The crypto directory must contain the built `fabrials_remote_noise.js` and `fabrials_remote_noise_bg.wasm`. Spanreed must contain the relay qualification fixture. Cargo builds the native host and relay test executables using their locked manifests; the runner imports Portable's actual `createRemoteTransport` and the actual Noise WASM.

The runner binds only loopback listeners and uses temporary owner-only state. It does not modify production endpoint constants or install a service. The native production socket loop is reused after fixture admission; the host's production OAuth/ticket acquisition and automatic reconnect supervisor are outside this test. The relay's ordinary WebSocket upgrade, routing, queue bounds and writer run unchanged. Its HTTP control-plane constructor is available only in test builds and accepts an explicit loopback address.

The account login and ticket persistence are simulated. Ticket consumption is single-use, expires by time, and returns the same strict identity/introspection contracts as the real control plane. Browser device storage is an isolated memory implementation in place of IndexedDB. The client requests its fixed production URLs; the runner intercepts exactly those network boundaries and rejects unexpected requests. This does not qualify production OAuth, TLS, cookie enforcement, browser IndexedDB or publication storage.

The acceptance checks cover:

- Pairing and bootstrap through Portable, WASM, the real relay and the native host.
- Read-only observation with the same grant and rejection of a borrowed controller epoch.
- Browser reconnect with the original grant and rejection of a stale epoch.
- Rejection of a resumed grant presented with another Noise device key.
- Account isolation, foreign-account relay routing, expired tickets and actual consumed-ticket replay.
- Native host restart with stable host identity, persisted pairing and device binding.
- Revocation acknowledgement, authenticated close, `not_paired` client classification and rejected resume.

The runner prints a path to `report.json` and retains process logs beside it. It removes fixture state and synthetic credentials on exit and stops only its own process groups. The native fixture is ignored during ordinary unit suites because it requires this driver; the driver explicitly runs it and checks its exit status. The relay fixture is inert without its explicit test environment.

On 2026-10-11 this chain exposed a relay shutdown race: a host-requested channel close set the browser's stop flag before queued encrypted frames reached it. The browser consequently saw a network failure instead of authenticated revocation. Host-requested channel closure now queues its terminal frame after prior ciphertext through the existing bounded delivery path; the browser writer stops after sending that frame. A single five-second deadline covers enqueueing, all pending writes and final closure; control traffic cannot extend it. Draining channels continue counting toward admission limits and remain reachable by immediate generation revocation, trust loss and host disconnection. Routing and writer regressions cover queued frame order, duplicate close, expired drain during a stalled send, continuous control traffic and immediate revocation. The end-to-end revocation check sends concurrent browser heartbeats; it failed before the fix and passed afterward.

## Live terminal prompt contract

The official Grok 1.0.50 terminal must start with `--leader`; `--leader-socket` alone selects a socket without enabling shared mode. Both terminal and Spanreed must use the same user and Grok home. Existing embedded sessions need an explicit `grok --leader --resume <session-id>` before they can share a live turn.

The live terminal acceptance found an omitted ACP capability: user messages were persisted but withheld from live clients. `AgentHandle` now opts into `clientCapabilities._meta["x.ai/userMessageEcho"]` at initialize and sends `_meta.clientUserMessageEcho` on session creation and loading. The host forwards the resulting `user_message_chunk`, preserving `hideFromScrollback` in both live and restored history. It never derives transcript text from queue display text.

Each host prompt carries a fresh UUID in `_meta.promptId`. Current Grok user chunks lack that ID: `turn.rs` constructs them using `build_notification_meta`, which includes only `eventId` and `agentTimestampMs`. The adapter therefore prefers the notification's explicit prompt ID, then the session's current `runningPromptId` from queue notifications, to distinguish its own echo from an identical terminal prompt. Replayed history bypasses live echo suppression. Older agents providing neither identity retain the existing text-prefix compatibility path; concurrent identical prompts cannot be distinguished reliably in that legacy mode.

`tests/fixtures/terminal_turn_1_0_50.json` contains selected actual ACP frames from the isolated 2026-10-11 terminal test, plus its user chunk from Grok's persisted transcript. Session and event identifiers are synthetic; the shell command belongs to the disposable fixture. The test substitutes only its session ID and replays data through the scripted agent, ACP reader, host journal and remote reconnect without executing tools. The scripted agent withholds live user chunks unless both capability and session opt-in are present. The test verifies one user prompt before assistant text and the tool, unchanged on reconnect. A second regression checks identical external prompts while a browser request is pending, an earlier queue snapshot, repeated snapshots, explicit IDs, hidden chunks, split own echoes and history replay. Removing initialization opt-in, load opt-in, identity matching or the replay guard each makes the relevant regression fail.
