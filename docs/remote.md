# Grok Remote implementation

Grok Remote is implemented across fabrials-libs, Spanreed, Portable and fabrials-web. The intended distribution is a single Spanreed executable with a compiled PWA, a separate relay service and the Fabrials account control plane. The 2026-10-11 station qualification covers real shared-leader protocol sessions, PostgreSQL/private S3, Linux lifecycle, Chromium PWA behavior and an installed Android PWA over real private Tailscale HTTPS. A real browser/CLI turn and the local integrated encrypted relay are also qualified. The deployed managed route and remaining native/mobile platforms still have separate acceptance gates below. This is a local source implementation, not a published release. Building it does not enable remote access automatically.

## Packages and integration

- `fabrials-agent-host`: shared Grok leader transport, lease checks, durable command receipts, typed ACP interactions, revocable browser grants, local control channel and exact private HTTPS origin support.
- `fabrials-remote-noise`: identical Snow 0.10 Noise XX / X25519 / ChaChaPoly / SHA256 implementation on Rust and WASM. The selected RustCrypto resolver also compiles without a C compiler on WASM.
- `fabrials-remote-host`: outbound relay connection, encrypted operation dispatch, host registration state and explicitly authorized public-session publisher.
- Spanreed's internal `spanreed-remote` library composes the host with the existing native installation login and refresh. `spanreed remote` runs inside the normal executable, preserving the existing atomic installer and self-update behavior. `spanreed-remote-relay` is the separate server.
- Portable builds the PWA at `remote.fabrials.com`; fabrials-web owns account authorization, single-use relay tickets, publication grants, private S3 revisions and the public reader.

Both new runtime crates are members of this canonical Cargo workspace and use its lockfile. The wasm-bindgen build helper under `tools/remote-bindgen` is separate. Canonical library edits must be committed before Spanreed's `scripts/sync-fabrials-libs.sh` imports them. A disposable consumer snapshot at `/tmp/fabrials-remote-integration` was used for compilation, preserving the real consumer's vendor tree. That snapshot is not a release source.

The four feature worktrees remain uncommitted. Canonical commits, official subtree synchronization and clean source provenance remain release gates; disposable checks do not perform them. Spanreed's source-integrity gate deliberately refuses to build the unsynchronized real checkout. The old restricted-runner GPG failure is historical, not a current environment diagnosis.

## Channel protocol

The relay URL is fixed to `wss://remote-relay.fabrials.com/connect` in host and browser. Admission is a one-use account ticket in the first WebSocket message, never a query parameter. Hosts connect outwards; the relay routes `open`, `data` and `closed` frames within one account/host namespace. It retains no command queue or conversation store.

Each browser channel performs fresh Noise XX with a prologue containing `fabrials.remote.v1`, host ID and channel ID. Before sending any credential, the browser checks the host public key against the local QR pairing or its saved pin. The last encrypted handshake payload carries the one-use local nonce or the saved session/CSRF grant. Device grants are bound to the authenticated browser static public key. A local-loopback grant is not a remote-device grant.

The application wire is closed: `command`, `subscribe` and `heartbeat`. It provides no raw ACP, arbitrary URL, filesystem-root or subprocess proxy. Commands retain the existing host operation allowlist and opaque workspace IDs. Share preview/start/stop are separate typed adapter operations. A response is `{type:"response",id,status,body}`; a host event is `{type:"event",event}`. Initial authorization returns `{type:"paired",body:<PairResult>}` inside encryption.

A rejected saved grant or a live device revocation sends `{type:"closed",reason:"revoked"}` inside the authenticated channel. An outer relay disconnect is a connectivity failure and cannot establish that a device grant was revoked.

An observing browser can revoke its own grant with the target-free `forgetBrowserPairing` operation. Revoking another grant or all grants still requires the controlling connection. Revocation commands acknowledge inside encryption before the channel performs its next authorization check, so a successful forget cannot race its own revoked close.

Noise messages are bounded to 65,535 bytes. The authenticated plaintext fragment header contains total byte size and exact offset, followed by at most 60,000 bytes. Total plaintext is bounded to 2 MiB + 16 KiB; browser requests to 256 KiB. Reordering, replay, authentication failure, invalid framing and exceeded bounds close the channel. The browser never falls back to plaintext or to another network route.

Private keys and grants reside in owner-only native state and origin-specific browser IndexedDB. Browser keys are extractable WASM inputs, not hardware-backed non-extractable keys. E2EE protects the conversation from the relay; the delivered PWA JavaScript remains trusted code. Snow is a third-party protocol implementation, not a claimed product security audit.

## Continuity and publication

Shared mode explicitly starts `grok agent --leader stdio` with the user's configuration and credentials. A terminal that should share live turns must also use `grok --leader`, with the same Grok home and leader socket. `--leader-socket` selects an endpoint but does not enable leader mode by itself. An already-running embedded terminal engine cannot be attached live: finish or explicitly cancel its turn, then reopen the saved session with `grok --leader --resume <session-id>`. This requirement was verified against the official 1.0.50 executable; Remote does not silently rewrite the user's Grok settings. Browser disconnect never implies cancel. One connection holds the mutation lease; observers cannot borrow another connection's epoch, even with the same browser grant. Reconnect obtains a fresh lease and replays events or requests snapshots. Explicit cancel remains a separate operation. Shared mode rejects the old direct shell shortcut.

Prompt receipt intent is persisted before dispatch. Uncertain outcomes are shown for manual reconciliation and never resubmitted automatically. There are at most 512 full receipts and 65,536 compact SHA256 tombstones under a 16 MiB state-file limit. Running and uncertain commands retain full receipts. Retired commands return `needsReview` / `receipt_expired`; capacity exhaustion refuses new effects rather than forgetting their identities.

Registration persists its pending static identity before contacting the account API. Retrying after a lost acknowledgement reuses that identity. Disable revokes locally and in the account control plane; reset requires disabled state, verified cloud revocation and an exclusive host lock. Account-owned revocation remains available after replacing a lost installation credential by linking a new installation to the same Fabrials owner. See Spanreed's `docs/remote.md` for the recovery sequence.

Owner-only `remote-status.json` reports connection and publication health independently. Connection timestamps expire after 35 seconds; a stale record never proves a live connection. Diagnostics contain bounded failure codes, not credential/provider error bodies. Transient ticket service failures are distinguished from rejected registration. The CLI reports these diagnostics separately from whether the local agent process is running.

Public sharing is explicit plaintext publication, separate from private control. The preview exports only user/assistant text, textual tool calls/results and diffs. It excludes reasoning, system messages, binary resources and arbitrary nested protocol fields. Publication consent includes future updates; each grant remains bound to its original session and does not follow forks. The native publisher continues after the browser closes. Ordinary message/tool text can itself contain secrets and remains visible in the preview.

Web authoritatively revokes a public link before the browser stops its local publisher. S3 content is private under `apps/spanreed-shares/`; readers pass current database authorization before and after loading it. Generation/revision checks prevent an in-flight upload from reviving a withdrawn link. Already downloaded copies cannot be recalled.

The PWA home lists active account publications and can withdraw them without opening a host connection. Observing browsers retain the public indicator and withdrawal action, while creating a publication requires control. A late preview or grant cannot silently start publication after control is lost. Backend admission bounds hosts, shares, outstanding tickets and publication-object reservations; maintenance drains superseded objects and expired tickets, and reports remaining work or failures.

## Concurrent browsers and lifecycle

The physical-phone investigation reproduced a two-tab hot loop of about 50 `/session` and 50 `/healthz` requests per second. A storage timestamp was being treated as new authorization, and resume rotated CSRF even when the presented grant was current. The host now preserves verified CSRF; Portable treats timestamp-only writes as unchanged authority. Portable serializes recovery across tabs with Web Locks where available and rereads the grant while holding the lock; the host idempotence described above also protects browsers without shared storage/locks. Changing the paired host replaces the destination before any credential-bearing request and clears old receipts, cursor and control state. The document reloads on actual authority replacement/removal to discard the old connection, conversation and forms. Generation/authority guards reject late pairing responses, including after JSON-body parsing, instead of restoring obsolete credentials.

Shared/private WebSocket connections now admit observers without evicting the controller. HTTP mutation authorization requires both the control epoch and an unpredictable connection token; the token lives only in that socket's client memory. Observers cannot borrow control even when they share the same browser pairing, and reconnect invalidates the old connection's authority. Three real-WebSocket regressions cover borrowed epochs, reconnect and observer revocation. The UI waits for an authorized controlling/watching hello before reporting Connected, and connection failures have a finite retry budget plus manual Retry.

The host `serve --help` path no longer starts the server. Two subprocess tests verify it exits promptly and leaves no host state.
